# Vector Poster

Apply this workflow before generating or editing an image.

## Goal

Prevent accidental instruction text, prompt language, drafting notes, or obvious spelling mistakes from appearing in the final image.

Treat the user's raw message as source material, not as a block of text that can automatically be rendered.

## 1. Separate instructions from visible content

Classify relevant text into two groups.

### INSTRUCTIONS — never render by default

Treat text as an instruction when it tells ChatGPT what to do, how to design the image, where the image will be used, or how the content is organized.

Examples include:

- ทำรูป
- ทำโปสเตอร์
- รวมไว้ใน 1 รูป
- ใช้สำหรับ LINE OA
- ใช้บรอดแคส
- รูปแยกกับข้อความ
- ข้อความที่จะโพสต์คือ
- ข้อความในรูปคือ
- ใช้ข้อความด้านล่าง
- ทำให้ดูพรีเมียม
- create an image
- design a poster
- image prompt
- prompt
- instruction
- design brief
- layout
- style direction
- negative prompt
- AI-generated instructions

Do not render these merely because they appear in the user's message.

### VISIBLE CONTENT — eligible to render

Treat text as visible content only when it is intended for the final audience to read in the image, such as:

- headline
- product name
- offer
- price
- feature
- date
- call to action
- contact information
- customer-facing disclaimer

When the user explicitly marks a section with wording such as "ข้อความที่จะโพสต์คือ", "ข้อความในรูป", "ใช้ข้อความต่อไปนี้", or an equivalent phrase, treat the marker itself as an instruction and treat the content after it as candidate visible content.

## 2. Build an approved text set

Before image generation, form an internal `APPROVED_VISIBLE_TEXT` set.

Only text from this set may be intentionally rendered.

Do not expose the label `APPROVED_VISIBLE_TEXT` in the image.

Do not add new headings, labels, badges, claims, prices, discounts, product facts, or calls to action unless the user asked for them or they are clearly derived from the supplied customer-facing copy.

If the user asks for an image with no text, keep the approved text set empty and do not invent text.

## 3. Proofread visible text

Proofread only the candidate visible content before approving it.

Check:

- Thai spelling
- English spelling
- obvious grammar errors
- duplicated words
- spacing around Thai/English text where appropriate
- punctuation
- units
- percentages
- currency formatting
- copied prices and quantities
- product names and proper nouns

Preserve the user's meaning.

Do not silently change a factual value, price, quantity, percentage, date, phone number, URL, product name, or proper noun unless the correction is unambiguous. If uncertain, preserve the source value.

## 4. Remove accidental meta text

Do not intentionally render prompt-like, instructional, or production-only wording, including equivalent Thai or English wording, unless the user explicitly intends that wording to be part of the audience-facing content.

Examples normally excluded:

- prompt
- image prompt
- generation prompt
- negative prompt
- instruction
- instructions
- description
- design brief
- creative brief
- style prompt
- AI generated
- generated by AI
- คำสั่ง
- คำสั่งสร้างภาพ
- ข้อความที่จะโพสต์คือ
- คำอธิบายสำหรับ AI
- โน้ตสำหรับคนออกแบบ

This is a semantic rule, not only a word blacklist. Remove equivalent production notes even when they use different wording.

Exception: if the user is intentionally creating educational or editorial content about prompts, AI instructions, or similar topics and explicitly wants those terms visible, allow them as normal audience-facing content.

## 5. Respect source images and supplied copy

When the user provides screenshots, photos, menus, price lists, or promotional copy:

- use them as the source of truth for visible factual text
- do not infer extra prices or promotions
- do not copy interface chrome, chat messages, filenames, timestamps, prompt text, or surrounding UI into the final artwork unless explicitly requested
- distinguish text that belongs to the source product/brand from text that belongs to the chat or editing workflow

## 6. Final preflight

Immediately before image generation, verify all of the following:

- Instructions are excluded from visible text.
- Prompt/meta/production notes are excluded.
- Thai and English visible copy has been proofread.
- Prices, numbers, percentages, dates, and units match the supplied source.
- Proper nouns and product names are preserved.
- No unsupported marketing claims were invented.
- No extra visible text was added without a reason.
- Only audience-facing content remains.

If the checks pass, generate or edit the image.

## 7. Output behavior

Do not make the user manually approve the cleaned text unless they asked to review copy first.

For ordinary image requests, perform this preflight silently and proceed with image generation.

If the user's request explicitly asks to see the cleaned copy before generating, show the proposed visible text first and wait for approval.

## Example

User message:

> ทำรูปรวมไว้ใน 1 รูปเพื่อใช้บรอดแคสใน LINE OA  
> รูปแยกกับข้อความ ข้อความที่จะโพสต์คือ  
> ⭐ เมล็ดกาแฟขายดีของร้าน  
> 250 กรัม ราคา 200 บาท

Interpretation:

- `ทำรูปรวมไว้ใน 1 รูปเพื่อใช้บรอดแคสใน LINE OA` → instruction, do not render
- `รูปแยกกับข้อความ ข้อความที่จะโพสต์คือ` → instruction/section marker, do not render
- `⭐ เมล็ดกาแฟขายดีของร้าน` → candidate visible content
- `250 กรัม ราคา 200 บาท` → candidate visible content

Generate the artwork using only the approved audience-facing copy.
